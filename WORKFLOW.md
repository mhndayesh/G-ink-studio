# Manga/Novel Creation Workflow — A to Z

Complete guide to creating a story in the correct order, based on the actual unlock system and data dependencies in the codebase.

---

## How the Unlock System Works

Every page has a **phase status** computed live from your story data:

| Status | Meaning |
|--------|---------|
| `locked` | Requirements not met — page is inaccessible |
| `in_progress` | Data exists but not complete |
| `completed` | All requirements met — unlocks dependent pages |
| `available` | Partially met — some features accessible |

**The system never stores a "completed" flag** — it recomputes status every time from your file content.

---

## The 6 Story Files

Your entire story lives in exactly 6 JSON files. Every approved chapter creates a frozen version snapshot of all 6.

| File | What it holds |
|------|--------------|
| `master_story.json` | Title, idea, genres, world type, factions, threats, world rules |
| `characters.json` | Major profiles (7 tabs, 150+ fields), side profiles, relationship map |
| `plot_outline.json` | Narrative structure, chapters, scenes, plot threads, **locations** |
| `chapter_script.json` | Pages → panels → dialogue, SFX, visual fields |
| `plot_workspace.json` | Free writing, AI expansion, consequence Q&A |
| `memory_system.json` | Auto-generated by system, never edited directly |

---

## Stage 1 — Foundation

### Step 1 · Story Seed *(required first — unlocks everything)*

**File:** `master_story.json`

Fill these to reach `master_story: completed`:
- **Title** — required
- **Idea So Far** — required (core narrative concept, 1–3 paragraphs)
- **Story Type** — required (select at least 1 genre/type from the list)

Optional on this page:
- Ending Direction
- Story Foundation notes

**AI tools available:**
- `AI Fill All` — suggests all fields at once from a brief prompt
- `AI Expand` — expands your idea text

> **Completion gate:** title + idea + ≥1 story type selected → unlocks World Core.

---

### Step 2 · World Core *(required — unlocks Cast)*

**File:** `master_story.json` (same file, different section)

Fill this to reach `world_core: completed`:
- **World Type** — required (single selection, e.g. modern, fantasy, sci-fi, historical)

Optional enrichment (add now or later):
- **World Master Rules** — magic, technology, power limits, forbidden rules, custom rules
- **Major Factions & Ruling Sides** — ruling side, opposing side, neutral/hidden sides, conflict map
- **Major Threats & Minor Side Threats** — main threat source, goal, target, stakes, time limit, hidden truth

**AI tools available:** AI-fill per section.

> **Completion gate:** world_type selected → unlocks Cast Forge.

---

## Stage 2 — Characters

### Step 3 · Cast Forge *(required — unlocks Plot Board)*

**File:** `characters.json`

Create your major character profiles. Each profile has 7 tabs:

1. **Status & Role** — character name, role level (protagonist/antagonist/etc.), story status
2. **Appearance** — visual style, body description, outfit, distinguishing features
3. **Faction Alignment** — which faction they belong to, loyalty level, allegiance type
4. **Backstory** — past history, mental state, place in the community, formative events
5. **Personality** — traits, behavior patterns, speech style, quirks, fears
6. **Powers** — origin, type, level, specific abilities, limits, cost
7. **Arc & Threats** — character arc journey, threat connections, personal stakes

**AI tools available:** Generate each tab individually with full story context.

> **Completion gate:** ≥1 major character profile created → unlocks Plot Board, Side Cast, Relationship Web, Faction Visuals.

> **Note:** The AI deep-merges partial input with your existing data — it won't overwrite what you've written.

---

### Step 4 · Side Cast *(optional — do before or after Plot Board)*

**File:** `characters.json`

Create supporting and minor characters. Each has 5 tabs (no Powers tab, no Arc tab):
Status & Role, Appearance, Faction Alignment, Backstory, Personality.

> No completion gate. The `sync-script-speakers` endpoint can auto-create stub side profiles for any speaker names that appear in your script but lack a profile.

---

### Step 5 · Relationship Web *(optional — requires ≥2 major profiles)*

**File:** `characters.json`

Define relationships between characters:
- Characters involved (e.g. "Kinji / Lorya")
- Relationship type (friend, rival, love interest, family, mentor, enemy, neutral, etc.)

**AI tools available:** `Analyze Relationships` — AI reads all major profiles and suggests new relationships to add.

> Requires ≥2 major profiles to unlock. Toggle the map on to activate.

---

### Step 6 · Faction Visuals *(optional)*

Generates AI visual identity prompts for each faction (armor styles, colors, insignia, etc.). Useful later for image generation. No completion gate, no blockers.

---

## Stage 3 — Plot

### Step 7 · Plot Board *(required — unlocks Script)*

**File:** `plot_outline.json`

**Part A — Narrative Structure** (select one):
- Three-Act Structure
- Hero's Journey
- Mystery Arc
- Kishotenketsu

**Part B — Story Arc Overview:**
arc_title, arc_summary, arc_themes, arc_pacing, story_arc_overview

**Part C — Chapters** (create at least 1 meaningful chapter):
Each chapter needs content in at least one of: chapter_title, chapter_purpose, summary, main_conflict, emotional_beat, twist_or_hook, ending_cliffhanger.

Per-chapter fields:
- chapter_title, chapter_purpose
- summary, characters_present, relationships_used, factions_used, threats_used
- world_rules_shown, power_system_shown
- main_conflict, emotional_beat, twist_or_hook, ending_cliffhanger
- structure_section (which act/stage this chapter belongs to)

**AI tools available:** Bulk chapter generation, per-chapter AI suggestions, arc structure guidance.

> **Completion gate:** narrative_structure selected + ≥1 meaningful chapter → unlocks Scene Cards, Plot Threads, Manga Script (pending Locations).

> **Gotcha:** Changing narrative structure later can optionally clear the chapter script — confirm the dialog carefully.

---

### Step 8 · Locations *(required before Script, Visuals, Export)*

**File:** `plot_outline.json` → nested at `content.locations.locations[]`

For each location, fill:
- **name** — required (this is what triggers `locations: completed`)
- **type** — interior, exterior, urban, nature, etc.
- **description** — what the place looks, feels, smells like
- **positive_prompt** — visual prompt for image generation
- **negative_prompt** — what to exclude from images

**AI tools available:**
- Per-location description generation
- `AI Generate All Locations` — bulk creates all locations from story context

> **Completion gate:** ≥1 location with a non-empty `name` → unlocks Manga Script, Visuals Studio, and Export. This is a hard blocker — do not skip.

> **Best practice:** Add a location for every distinct setting your chapters use. Panel `location_id` assignment in Visuals Studio depends on these names matching your scene cards' `location` field.

---

### Step 9 · Scene Cards *(optional but recommended)*

**File:** `plot_outline.json`

Break each chapter into individual scenes. Each scene has:
- scene_id (auto), chapter_id (FK to chapter), scene_order
- location (text — should match a Location name exactly)
- time, characters_present
- scene_goal, scene_conflict
- relationship_dynamic_used, new_information_revealed
- action_or_dialogue_focus
- visual_manga_moment, panel_mood, ending_beat

**AI tools available:** Per-chapter scene recommendations, bulk scene generation.

> **Not required for script generation** — if scenes are absent, `ChapterScriptService` synthesises a fallback scene from chapter data. But having scenes produces much better, more structured scripts with correct page-per-scene layout.

> **Gotcha:** The `location` field in each scene card should be spelled exactly as your Location's `name` — this is how `location_id` gets auto-stamped on pages during generation.

---

### Step 10 · Plot Threads *(optional)*

**File:** `plot_outline.json`

Define overarching narrative threads that span multiple chapters:
- **main_plot_thread** — singular goal and resolution
- **character_arc_threads[]** — per-character arcs
- **relationship_threads[]** — per-relationship arcs
- **threat_threads[]** — per-threat arcs
- **power_threads[]** — per-power system arcs

**AI tools available:** AI analyzes story + chapters and suggests all thread types.

> Not required for script generation. Good for keeping long stories coherent.

---

## Stage 4 — Write (Optional Planning)

### Step 11 · Writing Desk → Consequence Court *(optional)*

**File:** `plot_workspace.json`

A planning and reflection tool — not a production gate.

**Workflow:**
1. **Free Writing** — write your arc narrative or expand a chapter in your own words
2. **AI Complete** — AI expands/refines your writing (Light / Medium / Heavy / Dialogue-focused / etc.)
3. **Decision** — accept, reject, or edit the AI version
4. **Analyze** — backend extracts consequence questions from the story
5. **Consequence Court** — review and answer the questions (what happens next, what are the stakes, etc.)
6. **Approve** — marks workspace as approved

> This does NOT create a version snapshot. It's a thinking/planning layer. Production (versioning) happens in Manga Script.

---

## Stage 5 — Produce

### Step 12 · Manga Script *(required — main production step)*

**File:** `chapter_script.json`

**Prerequisites that must be met:**
- `plot_outline: completed` (narrative structure + ≥1 meaningful chapter)
- `locations: completed` (≥1 named location)
- Integrity lock not fully engaged

**Per-chapter workflow:**
1. **Generate** — AI builds pages from chapter data (+ scene cards if present)
   - One page per scene card (or one fallback page if no scenes)
   - 5 panels per page (default)
   - Dialogue, SFX, visual descriptions, narration generated
2. **Review/Edit** — patch individual panels, dialogue lines, SFX via the UI
3. **Approve** — auto-creates a version snapshot (v001 → v002 → v003 etc.) and freezes the chapter into history

**Batch generation:**
- `Generate All` button — runs all chapters in parallel on the server (one LLM call per chapter), then approves sequentially. Each chapter's LLM call receives only that chapter's slim context (not the full story) for speed.

**Chapter script lifecycle statuses:**
- `locked` → `ready` → `generated` → `approved` → `completed` (next_version_id exists)

> **Completion gate:** next_version_id exists (at least one chapter approved and snapshotted) → `chapter_script: completed`.

> **Gotcha:** Approving a chapter auto-creates the version snapshot. You don't need a separate "mark official" action.

> **Gotcha:** The integrity lock (`story_integrity_lock`) prevents re-generating chapters that have already been finalized. Use `Advance Lock` to move the lock forward once you're satisfied with a chapter range.

> **Gotcha:** `Load from History` has a guard — if the current working slot has unapproved content, you must approve or discard it before loading a different chapter.

---

### Step 13 · Visuals Studio *(optional but recommended before Export)*

**File:** `chapter_script.json` (patches panel visual fields)

**Prerequisites:** pages must exist (`chapter_script: available`), locations must be defined.

**What it does:**
Assigns visual metadata to every panel:
- `render_mode` — `t2i` (text-to-image), `i2i` (image-to-image for continuity), `layered` (char ref + location ref)
- `location_id` — which defined location this panel depicts
- Visual fields: visual description, character_action, background_details, facial_expression, pose_or_body_language, mood, narration

**Batch fill:**
- `Generate All Chapters` — processes every chapter sequentially, one at a time
- Each LLM call receives only that chapter's data + characters present in the chapter (slim context)
- Fills all panel visual fields in one LLM call per chapter
- Auto-approves and snapshots each chapter after fill

> **Gotcha:** After batch fill, each chapter gets a new version snapshot. This is correct behavior — the visuals fill is a production step, not just a metadata update.

---

### Step 14 · Export *(final step)*

**Prerequisites:** `plot_outline: completed`, `locations: completed`, integrity lock not fully engaged.

**What it exports:**
- Text / Markdown / DOCX / ZIP bundle of all 6 story files
- Validation report (see below)

**Validation before export:**
The system runs `ValidationService.validate_cross_references()` which checks:

| Severity | Example warnings |
|----------|-----------------|
| HIGH | Character in script has no profile (`missing_profile`) |
| HIGH | Script pages missing for a chapter (`missing_pages`) |
| MEDIUM | Panel has no `location_id` (`missing_location_id`) |
| INFO | Character name not lowercased (`name_case`) |

> Fix HIGH warnings before final export. MEDIUM can be tolerated. INFO is cosmetic.

```
FOUNDATION
  [ ] 1. Story Seed          title + idea + story type
  [ ] 2. World Core          world type selected

CHARACTERS
  [ ] 3. Cast Forge          ≥1 major character profile (all 7 tabs)
  [ ] 4. Side Cast           (optional) supporting characters
  [ ] 5. Relationship Web    (optional) requires ≥2 major profiles
  [ ] 6. Faction Visuals     (optional) visual identity per faction

PLOT
  [ ] 7. Plot Board          narrative structure + chapters
  [ ] 8. Locations           ≥1 named location  ← hard blocker for Script
  [ ] 9. Scene Cards         (optional but recommended) 1 scene per chapter
  [ ] 10. Plot Threads       (optional) overarching narrative threads

WRITE (optional)
  [ ] 11. Writing Desk       free writing + AI expand
  [ ] 12. Consequence Court  review consequences + approve

PRODUCE
  [ ] 13. Manga Script       generate → review → approve each chapter
  [ ] 14. Visuals Studio     (optional) assign locations + render modes to panels

EXPORT
  [ ] 15. Export             fix HIGH validation warnings → download
```

## Common Mistakes to Avoid

1. **Skipping Locations** — the single most common reason Script/Export is locked. You need ≥1 location with a name.

2. **Not filling `characters_present` in chapters** — the script generator uses this to know who's in the scene. The visuals batch fill uses it to filter which character profiles to send to the LLM.

3. **Leaving scene `location` field blank or mismatched** — the `location` text in a scene card should match a Location's `name` exactly (case-insensitive). This is how `location_id` gets stamped on pages at generation time.

4. **Re-generating an already-approved chapter** — the integrity lock prevents this, but if you generate over a chapter without approving the previous version first, you may lose that version's work from the working slot. Always approve before switching chapters.

5. **Approving without reviewing** — approval triggers an immediate version snapshot. Review dialogue, SFX, and panel descriptions before approving. Use `Load from History` if you need to go back.

6. **Missing side character profiles for script speakers** — if the LLM invents speaker names not in your profiles, use the `Side Characters → Sync Script Speakers` button to auto-create stub profiles for them, then flesh them out.

7. **Consequence Court before script** — Consequence Court and Writing Desk are planning tools. They do NOT create version snapshots. Don't treat them as a production step.
